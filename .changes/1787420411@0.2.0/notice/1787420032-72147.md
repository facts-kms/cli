# Release 0.2.0

This release adds the first HTTP collaboration interfaces to the `fact` CLI,
including local server hosting, bearer-token administration, authenticated
remote sync, and smoother bootstrap flows for clients cloning a shared ledger.

- Adds `fact http serve` to host one writable ledger, or all writable local
  ledgers, over the Facts HTTP transport with configurable bind address,
  public API root, and token store path.
- Adds `fact http token issue`, `list`, `revoke`, and `prune` for managing
  HTTP bearer tokens in a local SQLite token store. Token listing reports
  metadata without exposing token secrets.
- Adds `fact remote auth` for storing, reading from stdin, or clearing bearer
  tokens on configured remotes, and wires those tokens through personal
  `push`, `pull`, `clone --remote`, and low-level `sync` HTTP requests.
- Promotes `fact clone` into the visible command surface with `--remote`,
  `--ledger`, `--name`, and `--as` support, including writable clones when a
  local identity has signing material and ledger authority.
- Updates HTTP sync endpoints to the new object-push, object-pull, and
  object-fetch routes and lets remote pulls infer known object hashes from an
  existing local database.
- Adds `directory add --with-token` so service or human identities can be
  created and issued an HTTP access token in one flow.
- Polishes identity backup ergonomics: `fact identity export` now accepts an
  optional `[FILE]` and defaults to
  `<ledger>.identity.<actor-ref>.bundle` when omitted.
